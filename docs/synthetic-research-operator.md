# One-time synthetic survey email operator

Preparation only. This adapter has not been published, installed, run on a host, or used to send email. It is separate from the frozen activation/diagnostic bundle. It is not a public endpoint or a general-purpose mail tool.

## Required release gates

Before any host use, independently verify the exact approved release, the existing absolute Node 22 executable, the release working directory and module-loader/dependency compatibility, and the exact existing production SQLite path in the protected service environment. Verify the dedicated survey key is installed as `BUBBLEWASH_RESEARCH_RESEND_KEY`. Do not print or extract it. Do not substitute another service key, create credentials, install a runtime, initialize/migrate a database, change protected settings, or broaden access as a side effect of this adapter.

The caller must stream one bounded JSON object with the sole field `ownerEmail`, populated from the existing protected GitHub `BUBBLEWASH_OWNER_EMAIL`, over the already approved private operator channel. Do not place the address in command arguments, logs, artifacts, a persistent file, or new service settings. No manual recipient override is authorized. Protect stdin at its source and transport. The adapter cannot itself prove where the streamed value originated; the reviewed caller must enforce this custody.

## Invocation shape

From the verified exact release directory, use the existing verified absolute Node 22 executable with `--conditions=react-server --experimental-strip-types --experimental-loader=./tests/alias-loader.mjs`, followed by `scripts/send-synthetic-research-test.mjs --check --database <verified-absolute-existing-database>`. The database argument must resolve to the same existing file as the installed `BUBBLEWASH_DATABASE_PATH`; `NODE_ENV` must be `production`. Pipe private stdin as described above. Do not put secrets in the command. `--check` opens the database read-only and sends nothing.

After all release gates and applicable host execution authorization are satisfied, the same invocation with `--send` is the one-time action. It invokes the existing reviewed `sendSyntheticResearchTest` helper, not the general dispatcher. It saves only the helper's fixed adult synthetic response, claims its fixed submission key atomically, and attempts at most one email to the verified protected owner recipient only, with no CC or BCC. The outbox stores only the fixed `operator-test-only` recipient marker. The owner address is not persisted in the survey row. Ordinary respondent delivery remains `info@bubblewash.co`. There is no automatic retry.

The adapter compares the exact research table/index/trigger definitions with the reviewed SQL in an in-memory reference; it performs no target DDL, requires SQLite integrity and research foreign-key checks, enables connection-local foreign keys, and opens only an existing database. This is a focused survey check, not a substitute for the broader release/database readiness gate.

## Output and stopping rules

Only `{attempted,status}` is emitted. `ready` means local checks passed, not permission to send. `accepted` means provider acceptance, not inbox delivery. `already-attempted` means the fixed record cannot be sent again. `review-required` means stop and inspect privately; `attempted:null` means a send may have occurred before an exception. Never resend or reset/delete the synthetic record after any prior or uncertain attempt. `blocked` means preflight failed without invoking the helper. An interrupted process or missing result must also be treated as uncertain until private state is inspected; do not repeat `--send` as a diagnostic.

This change does not authorize publication, deployment, host execution, credentials, persistent settings, endpoint exposure, or additional emails. Before execution, include this exact three-file adapter in the approved source/release custody process and verify the private transport. Any change to the recipient, payload, key, service, permissions, or scope needs separate review/approval.
